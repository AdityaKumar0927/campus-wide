# Campus Wide — Architecture

Companion to `PLAN.md`. Facts marked "verified" were checked against official docs on 2026-09-15
(see `docs/research/2026-09-15-stack-verification.md`); items marked "verify" are checked before the
phase that needs them. Revised after the 2026-09-16 audit. This document evolves with the code.

## 1. System overview

```
 Browser / PWA                      Vercel (Next.js 16.3, Node 24)                 Supabase (free)
 ─────────────────                  ──────────────────────────────────────         ─────────────────────
 RSC + client islands   ──HTTPS──▶  proxy.ts  → RSC / Server Actions / Routes  ──▶ Postgres + RLS + pgvector
 Serwist service worker             (nonce, headers, session refresh)              Auth (magic link/OTP,
 Transformers.js worker             Data Access Layer  (src/lib/dal)                passkeys beta, captcha)
 (embeddings, toxicity)             ├─ supabase-js (user JWT → RLS)                Storage (images)
 Chrome Prompt API (opt)            └─ drizzle (schema, migrations, jobs)           Realtime (inbox only)
                                    Rate limit (Upstash) · Turnstile · Umami        pg_cron (sweeps, purge)
                                    Email (Resend SMTP + API) · Groq (opt-in, PII-free)
```

Scheduled work: Vercel cron (weekly digest + daily keep-alive ping; once/day is the Hobby minimum — verified), Supabase `pg_cron` (hourly expiry sweep, daily purge of accounts past the 30-day grace period, weekly stats refresh), GitHub Actions (CI; daily Supabase keep-alive against REST; nightly encrypted `pg_dump`). Supabase Edge Functions are deliberately not used: Vercel functions and `pg_cron` cover every need.

## 3. Tenancy model
- `universities` (id, slug, name, country, `settings` jsonb, `feature_flags` jsonb, `policy_text` jsonb, `safe_exchange_locations` jsonb, status). Flags and policy text are explicit columns, not buried in `settings`.
- `university_domains` (university_id, domain, verified, source: hipo|admin) — seeded from the Hipo list (MIT, verified). A demo campus is seeded until the owner names the pilot campus.
- `memberships` (user_id, university_id, `campus_role`: student|staff|alumni|moderator|university_admin, status: active|suspended|banned, sso_provider_id).
- **Tenant-implicit routing** (D-03): authenticated routes never carry the tenant; the DAL and RLS derive it from the caller. Public routes use `/campus/[slug]`.
- **Tenant claim**: a Supabase *Custom Access Token* hook (Postgres-function variant; verify Free-plan availability before Phase 2) adds **only** `university_id` to the JWT. **No `role` claim is ever written** — `role` is the reserved claim PostgREST uses for `SET ROLE` (anon/authenticated). RLS reads `app.current_university_id()` = `(auth.jwt()->>'university_id')::uuid`.
- **Roles are read from `memberships`**, not the JWT: `app.has_role(text)` is a STABLE SECURITY DEFINER function doing one indexed lookup on `(user_id, university_id)`, so demotions, suspensions, and bans apply immediately rather than at token refresh.
- Platform-level operators (`platform_admin`) exist outside any tenant and act only through audited service-role jobs and the admin portal.

## 4. Authentication and sessions
- **Sign-up**: email → domain matched against `university_domains` (exact or parent domain) in the form **and again in the database**: a Supabase *before-user-created* hook (verify availability; fallback: a BEFORE INSERT trigger on `auth.users` that raises for non-allowlisted domains) rejects addresses outside the allowlist even when the Auth endpoint is called directly. Allowed: `signInWithOtp` (magic link + 6-digit OTP, verified) → callback → a `SECURITY DEFINER` trigger on `auth.users` fires **when `email_confirmed_at` changes from null to a timestamp** (insert happens at OTP request, before verification) and creates `users`, `profiles`, `memberships` from the domain → consent gate → onboarding (display name, age attestation). Unknown domain → `domain_requests` row and a friendly "we will review" page.
- **Auth endpoint hardening** (the endpoints are reachable with the publishable key, bypassing app code): Turnstile captcha enabled in Supabase Auth settings; Supabase auth email rate limits configured; Upstash limits on the app-side sign-in action as a second layer.
- **Sessions**: cookie-based via `@supabase/ssr`; `proxy.ts` refreshes with `getClaims()`; the DAL calls `getClaims()` again (never `getSession()`) — verified guidance. The settings page lists the caller's sessions through a SECURITY DEFINER function over `auth.sessions` (created_at, updated_at, user_agent, ip — verify columns) and offers "sign out everywhere" (`signOut({ scope: 'global' })`).
- **Passkeys (Phase 2b, flag)**: `auth.experimental.passkey` with register / sign in / manage; an optional second sign-in path.
- **Recovery**: no passwords exist, so recovery = OTP to the verified university email. Because graduates lose that mailbox, users may add a **verified secondary email** and a passkey; either can be used to sign in after the primary mailbox is deactivated, and the account keeps its `alumni` role. Changing the primary email requires OTP on both addresses.
- **Future SSO**: Supabase SAML needs Pro (verified); `memberships.sso_provider_id` already exists so enabling SAML for one campus is configuration, not schema change.

## 5. Authorization: Data Access Layer + RLS (two independent layers)
- **DAL** (`src/lib/dal/*`): the only place that talks to the database. Each function receives a `Session` (claims + membership) and applies tenant, ownership, and role checks in code, then queries through supabase-js with the user JWT so **RLS enforces the same rules again**. Server Actions and route handlers call the DAL only; components never import the database.
- **RLS policy patterns** (declared with `pgPolicy` next to each table; `pgTable.withRLS` where a table has no policies yet — verified):
  1. *Tenant*: `university_id = app.current_university_id()` on every policy of every domain table.
  2. *Ownership*: `author_id = auth.uid()` for update/delete of own content.
  3. *Role*: `app.has_role('moderator')` (membership lookup) for moderation tables; `app.has_role('university_admin')` for settings.
  4. *Visibility*: rows with `deleted_at` or `moderation_status = 'hidden'` are visible only to the author and moderators.
  5. *Privacy*: `users.email` is never selectable by the `authenticated` role; profiles expose display name + pseudonymous handle only.
- **Service role** (Drizzle over the pooler with `prepare: false`, verified) is used solely by migrations, cron jobs, and platform-admin tasks, each with an `audit_log` entry.
- **Isolation tests** (`tests/rls`): for every table, seed two universities and users, then assert reads/writes across tenants fail as anon, as authenticated, and with a JWT whose `university_id` claim was tampered (signature check must reject it).

## 7. Masked contact relay (marketplace and other modules)
Double-blind, **in-app** threads with email notifications (D-14; deviates from the brief's email-relay wording, owner to confirm). No inbound-email parsing is required, so it runs entirely on free tiers:
1. Buyer taps "Contact" → `contact_relays` row + first `relay_message`; the seller gets an email notification (counted against the send budget) and an in-app inbox item.
2. Both parties chat in-app; neither sees the other's email or real name (display names only).
3. "Share my email" is a per-party opt-in; addresses are revealed in-thread **only when both** have opted in (`state = mutual_reveal`).
4. Threads expire with the listing; a report button sits in every thread; campus safe-exchange locations are shown in the thread header.
Upgrade path: a true email-in/email-out relay via Resend inbound routing if a campus wants it (verify Resend inbound docs at that time).

## 8. Moderation and appeals (DSA baseline)
- Every post/comment/thread has "Report" with category, free text, and optional evidence → `reports`.
- Moderators (trusted students or staff) work a queue; each action (`hide`, `remove`, `warn`, `suspend`, `ban`, `dismiss`) writes `moderation_actions.statement_of_reasons` {facts, ground (policy clause), automated: false, redress: appeal link} and notifies the affected user.
- Appeals: one per action, reviewed by a different moderator or an admin; outcome recorded; everything in `audit_log` (insert-only via trigger).
- Optional AI triage (Phase 6) only proposes labels and ordering for the queue; it never takes an action.

## 9. Notifications, digests, and scheduled jobs
- In-app: `notifications` table; the inbox page subscribes to one Realtime channel per user **only while open** (Free = 200 concurrent connections, verified) with a polling fallback; other pages show a badge from a cheap count query.
- Email: transactional (auth, relay, moderation) sent immediately; everything else folded into a **weekly digest** (Vercel cron) — a daily digest would exceed Resend's 100/day at roughly 80 opted-in users. A `send_budget` counter reserves headroom so auth mail is never blocked.
- Web Push (Phase 7): VAPID keys, `push_subscriptions`, install prompt before the permission prompt; iOS requires Home Screen install (verified).
- `pg_cron`: hourly `expire_posts()`, daily `purge_deleted_accounts()` (30-day grace; content anonymised, identity purged), weekly `refresh_campus_stats` materialized view.
- Keep-alive: a GitHub Action calls Supabase REST daily with the URL + publishable key from repo secrets (works before the app is deployed); after launch a daily Vercel cron pings `/api/health` too. GitHub disables schedules after 60 days without commits, so Dependabot activity or a monthly no-op commit keeps them alive.
- Backups: a nightly GitHub Action runs `pg_dump` over the direct connection, encrypts with `age` (public key in secrets, private key held by the owner offline), and uploads the artifact with 30-day retention. Unencrypted dumps never leave the runner.

## 10. Security controls (maps to `docs/BRIEF.md §6`)
| Control | Implementation |
|---|---|
| CVE-2025-29927 | Patched Next.js (≥ 15.2.3; we run 16.3.x), Vercel filters `x-middleware-subrequest` at its edge (verified), and authorization never lives in proxy. Proxy additionally drops the header before onward forwarding — defence in depth only, not a mitigation on its own |
| CSP | Per-request nonce in `proxy.ts`, passed via `x-nonce`; forces dynamic rendering (verified). Directive set: `default-src 'self'`; `script-src 'self' 'nonce-…' 'strict-dynamic' 'wasm-unsafe-eval' https://challenges.cloudflare.com <umami-host>`; `worker-src 'self' blob:`; `connect-src 'self' https://*.supabase.co wss://*.supabase.co https://huggingface.co https://*.huggingface.co https://*.hf.co <umami-host> https://challenges.cloudflare.com` (model CDN hosts verified at implementation); `frame-src https://challenges.cloudflare.com`; `img-src 'self' data: blob: https://*.supabase.co`; `font-src 'self'`; `style-src 'self' 'unsafe-inline'` (Sonner and Base UI inject styles at runtime without nonce support; a nonce would make unsafe-inline ignored, so inline CSS is accepted as a low-severity vector while scripts stay nonce-gated); `frame-ancestors 'none'`; `base-uri 'self'`; `form-action 'self'` |
| Other headers | HSTS (Vercel sets it for `*.vercel.app`), `Referrer-Policy: strict-origin-when-cross-origin`, `Permissions-Policy` (camera/mic/geolocation off), COOP `same-origin`, `X-Content-Type-Options: nosniff` |
| Input validation | Zod at every Server Action / route boundary; output is React-escaped; post bodies are plain text with link detection (no Markdown/HTML rendering in v1) |
| CSRF | Server Actions (origin-checked by Next); route handlers require same-origin + JSON content type |
| Rate limiting | Upstash sliding window keyed by user id or IP hash: sign-in 5/10 min, post 10/h, report 20/h, relay 30/h, feedback 5/h; **fails closed in production if Upstash is unconfigured**; in-memory limiter only in dev/test |
| Bot protection | Turnstile on sign-up (also enforced inside Supabase Auth), report, feedback, domain requests |
| Uploads | Client downscales/re-encodes to ≤ 1 MB before upload (protects the 5 GB egress budget) → signed upload URL → private bucket; server re-encodes with `sharp` to WebP ≤ 300 KB, strips EXIF, sniffs MIME from bytes; served via signed URLs |
| SSRF | `safeFetch()` allowlist for outbound hosts (Hipo API, Groq, Resend, GitHub); blocks private IP ranges and redirects to them |
| Secrets | `.env.local` (ignored) + Vercel env vars; `.env.example` documents every variable; gitleaks in CI |
| Supply chain | Committed `pnpm-lock.yaml`, `pnpm install --frozen-lockfile`, pnpm minimum-release-age (24 h; verify option name), provenance/signature verification where pnpm supports it (verify), Dependabot grouped weekly, CodeQL, `pnpm audit` in CI |
| Encryption | Supabase encrypts Postgres and Storage at rest and uses TLS in transit; relay tokens and IP addresses stored only as salted hashes |
| Backups | Nightly age-encrypted `pg_dump` (§9) |
| Audit | `audit_log` append-only for auth events, role changes, moderation, admin settings, exports, deletions |

## 11. AI (progressive, private by default)
- **Browser worker** (`src/lib/ai/worker.ts`): loads Transformers.js lazily, `device: "webgpu"` when `navigator.gpu` exists, else WASM; model downloads are gated on a non-metered connection (`navigator.connection.saveData` false, not `cellular` where reported) and cached in Cache Storage. Duplicate detection embeds the draft question on-device (mxbai-embed-xsmall or all-MiniLM, 384-d), calls a `match_questions(embedding)` RPC that runs a pgvector cosine search inside the tenant, and shows the top matches before posting; the same embedding is stored in `posts.embedding` when the post is created. The toxicity nudge classifies the draft before submit (toxic-bert baseline, ~110 MB; a MiniLM-sized classifier is evaluated in Phase 6) and only *asks the author to reconsider* — no AI rewrite.
- **Prompt API** (`LanguageModel`, Chrome 148+, desktop): an optional "summarise thread" button, shown only when `LanguageModel.availability()` reports ready.
- **Server (opt-in)**: Groq (no training, ZDR) behind `src/lib/ai/server.ts` with a PII scrubber (emails, phones, names from profiles) and a per-campus daily quota; used for thread summaries, translation, mod-queue triage labels, and event creation from pasted text. Every UI element that calls it is labelled "processed off-device". Gemini is excluded by default (trains on free-tier input). OpenRouter `:free` is a low-quota secondary.

## 12. PWA
`public/manifest.webmanifest`, maskable icons, theme colours for light/dark; service worker built from the Serwist core library by `scripts/build-sw.mjs` (esbuild) in `prebuild` → `public/sw.js`. Precache scope is deliberately small — `/offline` and static public assets — because a pre-build script cannot know Next's hashed output; `_next/static/*` is runtime-cached cache-first (immutable), pages network-first with offline fallback, fonts/images stale-while-revalidate. Push handler; install prompt component (deferred `beforeinstallprompt`, iOS instructions) shown before any notification permission request.

## 13. Front-end system
Tailwind v4 `@theme` with OKLCH semantic tokens (`--color-surface`, `--color-ink`, `--color-accent`…) following D-18 (warm paper neutrals, one campus accent hue, sans + serif display pairing, hairline rules), light/dark/system via next-themes (`class` strategy, no flash), self-hosted variable fonts via `next/font/local`, container queries for cards, `motion` for micro-interactions gated by `prefers-reduced-motion`, route transitions via `document.startViewTransition` where available (React's `<ViewTransition>` remains experimental — not used), mobile bottom nav with `env(safe-area-inset-bottom)`, desktop sidebar + `?`-triggered shortcut sheet, skeletons and empty states per module.

## 14. Analytics and observability
Umami (cookieless) script injected only when `NEXT_PUBLIC_UMAMI_*` is set and `navigator.globalPrivacyControl` is not true; field Core Web Vitals via Vercel Speed Insights (Hobby quota) or `web-vitals` events sent to Umami; `/api/health` for uptime + keep-alive; structured server logs; aggregate campus stats via a materialized view (no PII).
