## 1. System overview

```

 ─────────────────                  ──────────────────────────────────────         ─────────────────────

 (embeddings, toxicity)             ├─ supabase-js (user JWT → RLS)                Storage (images)

                                    Rate limit (Upstash) · Turnstile · Umami        pg_cron (sweeps)

```

Scheduled work: Vercel cron (daily digest, once/day on Hobby — verified), Supabase `pg_cron` (hourly expiry sweep, monthly purge), GitHub Actions (Supabase keep-alive every 5 days, CI).

## 3. Tenancy model
- `universities` (id, slug, name, country, settings jsonb, feature_flags jsonb, policy_text jsonb, status).
- `university_domains` (university_id, domain, verified, source: hipo|admin) — seeded from the Hipo list (MIT, verified).
- `memberships` (user_id, university_id, role: student|staff|alumni|moderator|university_admin, status: active|suspended|banned).
- **Tenant-implicit routing** (D-03): authenticated routes never carry the tenant; the DAL and RLS derive it from the caller. Public routes use `/campus/[slug]`.
- **Tenant claim**: a Supabase *Custom Access Token* auth hook adds `university_id` and `role` to the JWT at sign-in and refresh. RLS reads `app.current_university_id()` = `(auth.jwt()->>'university_id')::uuid`. Sensitive write policies additionally check `memberships.status = 'active'` so bans apply immediately, not at the next token refresh.
- Platform-level operators (`platform_admin`) exist outside any tenant and act only through audited service-role jobs and the admin portal.

## 4. Authentication and sessions
- **Sign-up**: email → domain extracted and matched against `university_domains` (exact or parent domain) → allowed: `signInWithOtp` (magic link + 6-digit OTP, verified) → callback → a `SECURITY DEFINER` trigger on `auth.users` creates `users`, `profiles`, `memberships` from the domain → consent gate → onboarding (display name, age attestation). Unknown domain → `domain_requests` row and a friendly "we will review" page; university admins and platform admins can approve.
- **Sessions**: cookie-based via `@supabase/ssr`; `proxy.ts` refreshes with `getClaims()`; the DAL calls `getClaims()` again (never `getSession()`) — verified guidance. Settings page lists sessions and offers "sign out everywhere" (`signOut({ scope: 'global' })`).
- **Passkeys (Phase 2b, flag)**: `auth.experimental.passkey` with register / sign in / manage; treated as an optional second sign-in path.
- **Future SSO**: Supabase SAML needs Pro (verified); the membership model already supports an `sso_provider_id` column so enabling SAML for one campus is configuration, not schema change.
- **Recovery**: no passwords exist, so recovery = OTP to the verified university email; changing email requires OTP on both addresses.

## 5. Authorization: Data Access Layer + RLS (two independent layers)
- **DAL** (`src/lib/dal/*`): the only place that talks to the database. Each function receives a `Session` (claims + membership) and applies tenant, ownership, and role checks in code, then queries through supabase-js with the user JWT so **RLS enforces the same rules again**. Server Actions and route handlers call the DAL only; components never import the database.
- **RLS policy patterns** (declared with `pgPolicy` next to each table, verified):
  1. *Tenant*: `university_id = app.current_university_id()` on every policy of every domain table.
  2. *Ownership*: `author_id = auth.uid()` for update/delete of own content.
  3. *Role*: `app.has_role('moderator')` for moderation tables; `app.has_role('university_admin')` for settings.
  4. *Visibility*: rows with `deleted_at` or `moderation_status = 'hidden'` are visible only to the author and moderators.
  5. *Privacy*: `users.email` is never selectable by the `authenticated` role; profiles expose display name + pseudonymous handle only.
- **Service role** (Drizzle over the pooler with `prepare: false`, verified) is used solely by migrations, cron jobs, and platform-admin tasks, each with an `audit_log` entry.
- **Isolation tests** (`tests/rls`): for every table, seed two universities and users, then assert reads/writes across tenants fail as anon, as authenticated, and with a JWT whose `university_id` claim was tampered (signature check must reject it).

## 7. Masked contact relay (marketplace and other modules)
Double-blind, **in-app** threads with email notifications — no inbound-email parsing is required, so it runs entirely on free tiers:
1. Buyer taps "Contact" → `contact_relays` row + first `relay_message`; seller gets an email notification (counts against the send budget) and an in-app inbox item.
2. Both parties chat in-app; neither sees the other's email or real name (display names only).
3. "Share my email" is a per-party opt-in; addresses are revealed in-thread **only when both** have opted in (`state = mutual_reveal`).
4. Threads expire with the listing; a report button sits in every thread.
Upgrade path: a true email-in/email-out relay via Resend inbound routing if a campus wants it (to be verified against Resend docs at that time).

## 8. Moderation and appeals (DSA baseline)
- Every post/comment/thread has "Report" with category, free text, and optional evidence → `reports`.
- Moderators (trusted students or staff) work a queue; each action (`hide`, `remove`, `warn`, `suspend`, `ban`, `dismiss`) writes `moderation_actions.statement_of_reasons` {facts, ground (policy clause), automated: false, redress: appeal link} and notifies the affected user.
- Appeals: one per action, reviewed by a different moderator or an admin; outcome recorded; everything in `audit_log` (insert-only via trigger).
- Optional AI triage (Phase 6) only proposes labels and ordering for the queue; it never takes an action.

## 9. Notifications, digests, and scheduled jobs
- In-app: `notifications` + Supabase Realtime channel per user; inbox page with mark-read.
- Email: transactional (auth, relay, moderation) sent immediately; everything else folded into a **daily digest** (Vercel cron, once/day on Hobby — verified). A `send_budget` counter in Redis/Postgres reserves headroom so auth mail is never blocked by the Resend 100/day cap.
- Web Push (Phase 7): VAPID keys, `push_subscriptions`, install prompt before the permission prompt; iOS requires Home Screen install (verified).
- `pg_cron`: hourly `expire_posts()`, daily `purge_deleted_accounts()` (30-day grace), weekly `refresh_campus_stats` materialized view.

## 10. Security controls (maps to `docs/BRIEF.md §6`)
| Control | Implementation |
|---|---|
| Header stripping | `proxy.ts` deletes `x-middleware-subrequest` from incoming requests; Vercel also filters it at the edge (verified) |
| CSP | Per-request nonce generated in `proxy.ts`, passed via `x-nonce`; `script-src 'nonce-…' 'strict-dynamic'`; forces dynamic rendering (verified) — accepted for an auth-gated app |
| Other headers | HSTS (preload), `Referrer-Policy: strict-origin-when-cross-origin`, `Permissions-Policy` (camera/mic/geolocation off), COOP `same-origin`, `X-Content-Type-Options: nosniff`, `frame-ancestors 'none'` |
| Input validation | Zod at every Server Action / route boundary; output is React-escaped; Markdown rendered through a sanitizer allowlist |
| CSRF | Server Actions (origin-checked by Next); route handlers require same-origin + JSON content type |
| Rate limiting | Upstash sliding window keyed by user id or IP hash: sign-in 5/10 min, post 10/h, report 20/h, relay 30/h, feedback 5/h; in-memory limiter when Upstash env is absent |
| Bot protection | Turnstile on sign-up, report, feedback, and domain requests |
| Uploads | Client → signed upload URL → private bucket; server re-encodes with `sharp` to WebP, strips EXIF, caps 5 MB in / 300 KB out; MIME sniffed from bytes; served via signed URLs |
| SSRF | `safeFetch()` allowlist for outbound hosts (Hipo API, Groq, Resend, GitHub); blocks private IP ranges and redirects to them |
| Secrets | `.env.local` (ignored) + Vercel env vars; `.env.example` documents every variable; gitleaks in CI |
| Supply chain | Committed `pnpm-lock.yaml`, `pnpm install --frozen-lockfile`, Dependabot grouped weekly, CodeQL, `pnpm audit` in CI |
| Audit | `audit_log` append-only for auth events, role changes, moderation, admin settings, exports, deletions |

## 11. AI (progressive, private by default)
- **Browser worker** (`src/lib/ai/worker.ts`): loads Transformers.js lazily, `device: "webgpu"` when `navigator.gpu` exists, else WASM; models cached in Cache Storage. Duplicate detection embeds the draft question and compares with recent question embeddings fetched as a small vector list; toxicity nudge classifies the draft before submit and only *suggests* a rewrite.
- **Prompt API** (`LanguageModel`, Chrome 148+, desktop): optional "summarise thread" and "make kinder" buttons, shown only when `LanguageModel.availability()` reports ready.
- **Server (opt-in)**: Groq (no training, ZDR) behind `src/lib/ai/server.ts` with a PII scrubber (emails, phones, names from profiles) and a per-campus daily quota; every UI element that calls it is labelled "processed off-device". Gemini is excluded by default (trains on free-tier input). OpenRouter `:free` is a low-quota secondary.

## 12. PWA
`public/manifest.webmanifest`, maskable icons, theme colours for light/dark; service worker built from the Serwist core library by `scripts/build-sw.mjs` (esbuild) in `prebuild` → `public/sw.js`; precache app shell + `/offline`; runtime caching for fonts/images (stale-while-revalidate); push handler; install prompt component (deferred `beforeinstallprompt`, iOS instructions) shown before any notification permission request.

## 13. Front-end system
Tailwind v4 `@theme` with OKLCH semantic tokens (`--color-surface`, `--color-ink`, `--color-accent`…), light/dark/system via next-themes (`class` strategy, no flash), self-hosted variable fonts via `next/font/local`, container queries for cards, `motion` for micro-interactions gated by `prefers-reduced-motion`, View Transitions for route changes, mobile bottom nav with `env(safe-area-inset-bottom)`, desktop sidebar + `?`-triggered shortcut sheet, skeletons and empty states per module.

## 14. Analytics and observability
Umami (cookieless) script injected only when `NEXT_PUBLIC_UMAMI_*` is set; Global Privacy Control respected (script skipped when `navigator.globalPrivacyControl` is true); `/api/health` for uptime + keep-alive; structured server logs; aggregate campus stats via a materialized view (no PII).
